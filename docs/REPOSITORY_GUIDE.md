# Repository guide

## Main reproducible experiments

- **Matching:** `code/30_compare_matching_methods.py` — three approaches on a common 113-identity gallery. Results in `results/matching_comparison/`.
- **Segmentation sensitivity:** `code/28_segmentation_sensitivity.py` — controlled threshold and ground-removal comparison. Results in `results/segmentation_sensitivity/`.
- **Human visual audit:** `code/29_visual_segmentation_validation.py` — interactive human ratings. Results in `results/visual_validation/`.
- **Skeleton/junction prototype:** `code/27_batch_tree_pipeline.py` — exploratory mapping of five examples. Results in `results/batch_junctions/`.

## Earlier code

Scripts `01`–`25` (and `27`) document developmental approaches to inspection, depth features, geometry, skeletonisation, branch tracing and mapping. They are **not** all required to reproduce the current controlled matching comparison. Do not move or rename these without checking scripts that import or read their outputs. There is no `26` script in the current repository.

## Verification

`tests/test_matching_methods.py` provides self-contained synthetic tests for the functions in script 30. These are **unit verification** tests: they demonstrate mathematical and software behaviour for constructed examples, not the ability to identify apple trees in an independent orchard.

Run:

```bash
python -m pytest tests -v
```

The GitHub Actions workflow `.github/workflows/verify.yml` additionally checks compilation, saves a text/JUnit test report, and generates source-code HTML pages with pdoc. Under the repository **Actions** tab, open the latest *Numerical tests and HTML documentation* run and download its `numerical-tests-and-html-docs` artifact. Tests and docs are not considered verified until a successful run is recorded. HTML is generated by CI, not committed as build output.
